#### Goal: join the Windows client VM to lab.local

### 7:40 PM

Built the client VM. Windows 11 eval ISO, 4GB RAM, NAT network, same VMnet as the DC.

Set a static IP the same way as DC01, just a different address on the subnet:

```
New-NetIPAddress -InterfaceAlias "Ethernet0" -IPAddress 192.168.174.20 -PrefixLength 24 -DefaultGateway 192.168.174.2
Set-DnsClientServerAddress -InterfaceAlias "Ethernet0" -ServerAddresses 192.168.174.10
```

Important difference from the DC: DNS points at DC01's IP (192.168.174.10), not 127.0.0.1. A client resolves through the DC, it doesn't try to be its own DNS server.

Tested with `Resolve-DnsName lab.local` and got a timeout.

Spent a minute thinking the static IP or DNS config was wrong again. It wasn't. DC01 was just powered off. No DC running means nothing is listening on 192.168.174.10 to answer the query. Turned DC01 on, ran the same command again, resolved fine.

Lesson: check the DC VM is actually running before troubleshooting DNS on a client. Would've saved me the detour.

### 8:10 PM

Joined the domain. Right-click Start > System > Rename this PC (advanced) > Change, selected Domain, typed `lab.local`, authenticated as `LAB\Administrator`.

Got a weird error dialog on the way:

> Changing the Primary Domain DNS name of this computer to "" failed. The name will remain "lab.local". The error was: The specified domain either does not exist or could not be contacted.

Confusing wording, looked like a failure at first glance, but it's actually about the DNS suffix setting specifically, not the domain join itself. The join had already gone through, this error is a known cosmetic/DNS-suffix side effect that shows up sometimes right after a successful join.

Confirmed the real state directly instead of trusting the dialog:

```
(Get-WmiObject Win32_ComputerSystem).Domain
(Get-WmiObject Win32_ComputerSystem).PartOfDomain
```

Came back `lab.local` / `True`. Actually joined.

Restarted, logged in as a domain user to prove it end to end.
